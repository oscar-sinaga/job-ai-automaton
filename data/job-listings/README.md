## Cara memakai

- HTML: pencarian lintas judul/perusahaan/skill/detail; filter tanggal WIB, bidang, tipe pekerjaan, pengaturan kerja, sumber, lokasi, cakupan feed, dan cakupan deskripsi. Filter dapat digabung. Buka kartu untuk detail, tautan sumber, serta seluruh pengamatan asli. Tautan detail di tabel di atas juga dapat dibuka langsung di HTML.
- Excel: sheet **Jobs** berisi satu baris per identitas dengan tabel berfilter, freeze header, tautan sumber dan detail HTML. **Observations** berisi satu baris per kejadian; filter `run_date_wib` di sini untuk pencocokan tanggal yang tepat. `first_seen_wib`/`last_seen_wib` pada Jobs adalah batas pengamatan, bukan rentang ketersediaan yang terus-menerus.
- **Descriptions** menampilkan ringkasan arsip, bagian parafrasa, asal sumber, waktu/cakupan dan status teks mentah. **Sources** menyimpan semua tautan historis. **Fields** menyimpan setiap field pengamatan sebagai JSON; **Runs** menyimpan seluruh metadata run; **Enrichment** menyimpan seluruh metadata tambahan; **Archives** menyimpan SHA-256 seluruh sembilan arsip awal. Teks panjang dipecah menjadi bagian bernomor agar batas sel Excel tidak memangkas data.
- JSON: `jobs[]` menyimpan field tampilan, `observations[]` lengkap dan `description`; `runs[]` menyimpan metadata lengkap tanpa menghilangkan catatan/exclusions; exclusions berada di pengamatan masing-masing job. `archives[]` memuat checksum untuk seluruh varian arsip harian.

## Identitas, tanggal, dan batasan

Deduplikasi hanya berdasarkan pasangan platform dan `source_job_id` yang sama setelah trim; platform dinormalisasi ke huruf kecil. Jika tidak ada ID platform, gunakan `id` eksplisit, kemudian URL dengan parameter pelacakan yang dikenal dihapus, lalu identitas baris arsip sebagai fallback. Judul/perusahaan yang mirip dan listing lintas platform **tidak digabung otomatis**. Sumber pemberi kerja dan sumber tambahan tetap dibedakan dari identitas platform.

Semua 31 pengamatan listing dan tujuh catatan pengecualian awal dipertahankan, termasuk satu pengecualian duplikat Alodokter dan dua pengamatan penutupan Indocyber. Keduanya menjadi masing-masing satu identitas tanpa menghapus kejadian sebelumnya. Lima identitas hanya pernah tercatat sebagai dikecualikan; gunakan `feed_state` untuk memisahkannya. Catatan duplikat bukan tanda lowongan ditutup. Field tampilan berasal dari listing terakhir jika ada; pengecualian berikutnya tidak menghapus rincian listing. Seluruh versi asli tetap ada di `observations[].record`.

Tanggal filter adalah tanggal **pengumpulan WIB** dari run, bukan tanggal posting atau jaminan status live. Tanggal posting relatif dipertahankan apa adanya; tidak dihitung menjadi tanggal pasti. Nilai yang tidak diketahui tetap `null` pada JSON/kosong di Excel. Header bagian ringkasan arsip merupakan pengelompokan editorial; tidak diklaim sebagai susunan asli lowongan.

Teks lengkap tidak tersimpan pada arsip awal. Tujuh tambahan berupa parafrasa bagian halaman yang dapat dibaca, bukan reproduksi penuh. Lima upaya enrichment JobStreet gagal mengakses detail melalui tool; ringkasan historis tetap tersedia tanpa klaim verifikasi ulang. Lima identitas excluded-only tidak memiliki deskripsi. Belum ada teks mentah tersimpan.

Sumber tambahan Teleperformance/TP dan Grab ditemukan terpisah; kaitan langsung ke ID JobStreet belum dibuktikan. Benefit Grab bersifat global dan kelayakan lokal belum disebutkan. Konflik employer ICUBE/Graha Karya Informasi, perbedaan kualifikasi Motasa, peringatan verifikasi hirer Grab, serta konflik status Thales dipertahankan. Halaman resmi tambahan Thales menyatakan lowongan tidak tersedia, sementara LinkedIn masih memperlihatkan deskripsi/kontrol aplikasi; hubungan langsung kedua ID belum dibuktikan. Tombol Apply tidak membuktikan lowongan masih menerima lamaran. Pengambilan web dapat berupa cache.

## Regenerasi untuk pembaruan harian

Jalankan dari root repository (tidak menggunakan aplikasi, database, API AI, atau akses jaringan saat regenerasi):

```bash
python -m venv /tmp/job-listings-venv
/tmp/job-listings-venv/bin/pip install -r data/job-listings/requirements.txt
/tmp/job-listings-venv/bin/python data/job-listings/tools/regenerate.py
/tmp/job-listings-venv/bin/python data/job-listings/tools/verify.py
```

Verifikasi browser memakai Chromium. Jika belum tersedia, instal dengan `python -m playwright install chromium`, atau set `CHROMIUM_PATH` ke executable lokal. Verifikasi merender byte HTML dalam Chromium tanpa mengunjungi situs lowongan. Browser terkelola pada sesi ini memblokir navigasi `file://`, sehingga pengujian menggunakan `set_content`; pembukaan file melalui navigasi langsung belum diuji di lingkungan ini.

Tambahkan arsip `YYYY-MM-DD.json` berikutnya dengan format harian yang ada, lalu jalankan ulang generator dan verifikasi. `run_date_wib` harus sama dengan nama berkas dan `listing_count` harus sesuai. Generator hanya membaca JSON bertanggal, tidak membaca kembali output konsolidasi sebagai input. CSV/Markdown harian adalah proyeksi/catatan pendamping, tidak dihitung sebagai pengamatan baru. `enrichment.json` adalah **input opsional**, bukan JSON konsolidasi kedua. Generator tidak menjadwalkan atau mengubah proses koleksi harian; jalankan setelah penambahan arsip. Gunakan `--output-dir /tmp/job-preview` untuk preview sebelum memperbarui hasil utama.

Semua tooling dan hasil berada di folder data ini. Tidak ada perubahan kode/config/workflow aplikasi. Hasil deterministik: input dan template yang sama menghasilkan JSON, HTML dan workbook dengan byte yang sama.

## Kontrak enrichment opsional (v1)

Tambahkan/ubah `enrichment.json` dengan `schema_version: 1` dan `jobs` berupa objek keyed by ID stabil. Enrichment menambah detail terpisah, tidak menulis ulang arsip atau pengamatan platform. Contoh:

```json
{
  "schema_version": 1,
  "jobs": {
    "linkedin:4482416376": {
      "source_url": "https://www.linkedin.com/jobs/view/4482416376/",
      "observed_at": null,
      "observation_window_utc": "2026-11-05T01:30:41Z/2026-11-05T01:32:18Z",
      "completeness": "sectioned_paraphrase_not_full_text",
      "raw_text_availability": "not_collected",
      "sections": [
        {"heading": "Responsibilities", "text": "Parafrasa faktual berdasarkan bagian sumber."}
      ],
      "provenance": "Metode akses, batasan cache dan identitas sumber."
    }
  }
}
```

`source_url` wajib HTTP(S). Isi `observed_at` dengan timestamp berzona jika tersedia; jika waktu tepat tidak diketahui, biarkan `null` dan isi `observation_window_utc` dengan batas awal/akhir berzona (inklusif). Jangan membuat timestamp pasti dari suatu rentang.

`completeness` menerima `summary_only`, `partial`, `sectioned_paraphrase_not_full_text`, `supplemental_matching_platform_paraphrase`, `supplemental_matching_official_paraphrase`, `not_enriched_detail_unavailable`, atau `complete_user_supplied` (alias `detailed_paraphrase` dan `detailed_paraphrase_of_accessible_description` juga diterima). `sections` harus berupa daftar pasangan `heading`/`text`; pertahankan urutan sumber sejauh diketahui. Bagian yang tidak disebutkan ditandai jujur, tanpa menambah persyaratan/benefit. Jika enrichment tidak memiliki bagian, cakupan tampilan tetap berdasarkan ringkasan arsip yang tersedia.

`raw_text_availability` menerima `not_collected`, `unavailable`, atau `user_supplied`. Field `raw_text` hanya diterima untuk teks yang memang disediakan pengguna, dengan status `user_supplied`. `complete_user_supplied` wajib memiliki teks tersebut. `raw_text_available` boolean lama dapat dipertahankan sebagai metadata, tetapi status eksplisit di atas menjadi acuan. Jangan baru menyalin teks lengkap pihak ketiga. Gunakan parafrasa dan, jika perlu, `short_excerpts` berupa daftar kutipan singkat (maksimum gabungan 25 kata per URL sumber pada file enrichment).

Catatan akses/status dapat memakai `provenance`, `retrieval_status`, `availability_status`, `official_application_status`, `supplemental_official_url`, `official_job_id`, `availability_conflict`, dan `official_observation_window_utc`. Konflik tampil jelas di HTML/Excel. Opsional `source_observations` adalah daftar `{source_url, observed_at, status, note}`; misalnya status `official_closed`, tetap terpisah dari status platform historis. Seluruh field input tambahan dipertahankan di JSON dan sheet Enrichment. Jangan menyimpulkan identitas requisition yang belum dibuktikan.
